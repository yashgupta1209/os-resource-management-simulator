Simulate Process Resource Request

According to Banker's Resource-Request Algorithm:

  1. If Request[i] ≤ Need[i], proceed; otherwise raise error (exceeded maximum claim).
  2. If Request[i] ≤ Available, proceed; otherwise process must wait (insufficient resources).
  3. Pretend to allocate: Available = Available - Request, Allocation = Allocation + Request, Need = Need - Request.
  4. Run Safety Algorithm. If safe, grant request permanently; if unsafe, roll back to original state.

4. Viva / Defense Preparation Questions & Answers

Q1: What is the difference between an Unsafe State and a Deadlocked State?

Ans: An unsafe state is NOT necessarily a deadlock; it is a state from which a deadlock is possible if all processes request their maximum resources at once. A deadlocked state is a state where processes are actually stuck waiting for each other and cannot proceed.

Q2: What is the time complexity of Banker's Algorithm?

Ans: For n processes and m resource types, the time complexity is O(m × n²). In the worst case, we search through n processes, each needing m comparisons, repeated up to n times.

Q3: Why does Banker's Algorithm require processes to state their Maximum demand in advance?

Ans: Banker's algorithm is an avoidance algorithm. To guarantee the system will never enter a state where resource exhaustion causes deadlock, the OS must know the upper bound of each process's resource needs beforehand.
